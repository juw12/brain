Kilat - a small typed scripting language with units and a sandbox ("kilat" is Malay for lightning)

  • Repo: https://github.com/juw12/kilat (public, MIT)
  • Live: https://juw12.github.io/kilat/ (playground: edit the code, press Run)
  • Guide: https://github.com/juw12/kilat/blob/main/docs/LANGUAGE.md
  • Results: https://github.com/juw12/kilat/blob/main/RESULTS.md

What it is

A small language for calculations and safe scripting. Types and units are checked, so a mistake such as adding metres to seconds is refused instead of printing a wrong number. Programs run inside a sandbox with a step budget (fuel) and a memory limit, so an endless loop or a runaway allocation is stopped.

Measured (judge script, run 2 of 2)

  • Speed (version 0.2.0): 3.06x CPython 3.13 on CPU time over 10 benchmarks, 2.62x net of start-up. The 5x target was not met. Net of start-up it is faster on 9 of 10 and about level on strings; none is slower. (Version 0.1 measured 2.82x and 2.43x and was slower on strings and map_count.)
  • Fuzz and differential test: 11,607 cases, 0 failures, 0 worker restarts (test and its Python reference written by the same author as the language).
  • Bugs refused before running: Kilat 20/20, mypy --strict 14/20, plain CPython 0/20 (author-written bug set).
  • Run 2 passed every check. Run 1 failed one page-freeze timing check (526 ms against a 500 ms limit) while the PC was going to sleep.

Where it fits

  • Cairn: a plugin that renders kilat code blocks with their results. Install: Plugins, "Install from GitHub or a link", type juw12/kilat. Tested in the real Cairn web app (demo brain, headless Edge): 8 of 8 checks, twice. Catalogue pull request: https://github.com/juw12/cairn/pull/35 (open). The in-app install from GitHub and the desktop build are not tested.
  • Glow: run model-written Kilat in the WebAssembly sandbox with fuel and memory limits, and feed type and unit errors back to the model. host(name, payload) is the gate where an app adds its own functions. GlowCode page (a person or a model writes Kilat, the checker gates it before it runs): https://github.com/juw12/projects/pull/53 (open; tested with a stand-in model only).
  • Other projects: kilat.run(source) from Python, loadKilat() from JavaScript, kilat run on the command line.

Limits

  • Not better than Python overall: no package ecosystem, no debugger or editor support. The release files are unsigned.
  • Known fault: a fuel stop can report the wrong place for an empty while true { } loop (the program is still stopped).
  • Nobody else has written a bug set or repeated the measurements.
  • Floating point overflow gives inf and nan, as in other languages.

  • Three usability defects I found in Kilat:
    1. rpm is silently an angular speed, so models convert twice (rpm * 2 * pi / 60). One wrong number got through: 471.7 where 49.39 was expected.
    2. expr in J seems to give a bare number, then {energy:J.3} is refused.
    3. {x} without a unit prints base SI plus its label, so models add a second unit ("96 N N").
  • Plan for 0.2.2 (not started): checker hint for the rpm double conversion plus a prompt line; make in <unit> work with a unit placeholder or refuse with a clear hint; refuse a unit word right after a unit-less placeholder. Then rerun the spaced sample.
