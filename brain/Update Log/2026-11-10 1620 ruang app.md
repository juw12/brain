# ruang: now an installable app (Windows exe + phone/desktop PWA)

Asked: "make it into app, not html".

## Shipped
- **Windows desktop app**: Tauri 2 shell (`desktop/`) with the web app embedded; one portable exe, opens in its own window, offline.
  Release v1.1.0: https://github.com/juw12/ruang/releases/tag/v1.1.0 (`Ruang-1.1.0-windows-x64.exe`, 3,986,432 bytes, SHA256SUMS attached).
- **Phone + desktop install (PWA)**: manifest with id/scope + PNG and maskable icons, apple-touch-icon, service worker `sw.js` (offline cache of the app shell, 3D engine, style thumbs and sample room). Live manifest and sw.js return 200 on Pages.
- Share links made in the desktop app point at the public web app.
- CI `.github/workflows/desktop.yml` on windows-latest: build exe, check WebView2, smoke-test the real window, attach exe to the release on `v*` tags.
- README: "Install it as an app" table (Windows / Android / iPhone / Mac-Linux-Chromebook).

## Verified
- CI desktop smoke 11/11 in the real WebView2 window (Edge 156): page from tauri.localhost, boots, desktop mode, no service worker inside the exe, 3D canvas, sample room builds 3.6 m x 4.55 m, share base = public URL, no JS errors, screenshot.
- Release asset download returns 200.
- Web gates before the app work: G1 54/54, i18n, e2e, 390 px phone (all pass).

## Not done / limits
- No local exe build: this PC has no MSVC link.exe or windres; the exe is built on GitHub Actions.
- Exe is not code-signed (SmartScreen "More info -> Run anyway").
- Phones install the PWA; no store APK/IPA.
- Local re-run of the browser e2e gates after the last JS change timed out on page load (machine overloaded); the change only adds two functions to `window.__ruang`, and the CI smoke exercises them.
